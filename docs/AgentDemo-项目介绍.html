01 Why this project

让对话，
连接真实的工作。

从个人资料问答开始，把读取信息、调用工具和持续执行放进同一个工作区。

本地优先：应用和主要数据可以部署在本机。
聊天与 embedding 仍可调用远端模型 API。

  1. 01

    有资料可查

    上传文档后检索相关片段，把来源带进回答；会话历史与摘要补充前后文。

    “这份设计文档中，租约机制解决了什么问题？”

  2. 02

    有工具可用

    读取本地文件、抓取网页、搜索信息，或通过 MCP 接入外部能力。执行过程可以查看与审计。

    “读取这个 GitHub 仓库，说明主要模块。”

  3. 03

    有任务可追踪

    把耗时请求交给后台，查看状态与结果；也可以创建一次性、间隔或每日执行的任务。

    “把这次资料总结放到后台执行。”

05 A boundary for action

工具接入可以扩展，
执行边界始终集中。

工具名、参数和执行意图，
最终都要经过 ToolExecutor。

  1. 执行前

    先检查，再行动

    检查工具启用状态、确认要求与参数 schema。需要确认的动作先返回确认状态，等待后续请求。

  2. 执行中

    控制等待与输出

    应用超时和输出限制，避免外部工具长期占用请求，或把过大内容直接灌入上下文。

  3. 执行后

    让结果与记录一致

    将 MCP 的 isError 规范成失败结果，并持久化调用审计，让 UI、模型上下文与数据库对失败有一致理解。

超时表示等待结束；同步线程中的动作仍可能继续。插件也不等同于沙箱。阅读执行边界

07 Work beyond a connection

任务的生命周期，
可以长于一次连接。

状态留在数据库里。
浏览器不必一直保持聊天连接。

BACKGROUND EXECUTION执行路径示意
queued

任务入库，等待领取

提交返回任务 ID，前端可以查询状态。
running

抢占任务，复用 Runtime

行锁负责领取，心跳持续续约。
↳ queued

失败后按退避策略重试

可重试失败后重新排队，受次数预算约束。
succeeded

保存结果与执行记录

其他终态包括 failed、cancelled、stale。

支持一次性、间隔与每日调度。调度发生键用于去重，外部副作用仍需独立幂等设计。

2单个调度器默认并发
3次最多尝试次数
15秒默认心跳间隔
180秒默认租约时长

租约过期后有恢复依据，重试时仍可能重复调用工具。当前恢复发生在任务层，没有保存 LangGraph 节点检查点，也不保证外部动作 exactly once。

行锁解决当前领取冲突；租约帮助识别失去响应的执行。阅读任务执行器

09 What comes next

把能力连起来，
也把边界讲清楚。

这个项目的重点，是把 Agent 放进可维护的应用流程。下一步的改进，需要落到明确的失败场景和验证方法。

01 / PLANNING

从规则走向通用规划

现在：规则路由、工具名匹配和有界循环，没有原生 Function Calling。

下一步：结构化工具调用、参数解析与统一调用预算，用复合任务题集验证。

02 / RECOVERY

让确认真正可恢复

现在：确认通过独立接口续跑，图没有 checkpointer，待审批动作未完整持久化。

下一步：持久化审批 ID、绑定参数并防止重放，验证刷新、重试与重复点击。

03 / EVALUATION

从流程正确到效果可靠

现在：向量优先检索、关键词降级、会话摘要，回答文本完整缓冲后输出。

下一步：真实任务评测、引用支持度、token 与延迟统计，再决定重排和流式策略。

找得到依据，调得动工具，
也看得清执行过程。
