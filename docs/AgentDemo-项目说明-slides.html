# understand · act · remember

01 / Product north star

不只是聊天框

把「提问—理解—行动—记忆」串成一个可观察、可控制、可持续演进的工作闭环。

01

本地优先

数据与运行环境尽可能留在本机，便于掌控隐私、成本与依赖。

02

过程透明

状态、计划、工具调用和结果都通过流式事件呈现，而非只给最终答案。

03

安全行动

外部能力统一经过验证、确认、超时、限流和审计边界。

04

长期上下文

会话、RAG 与摘要记忆共同构成可延续的个人知识环境。

02 / User experience

一个对话入口，四类工作空间

Conversation

持续对话

创建会话、回看历史、流式接收回答，并保持上下文连续。

Runtime

运行时观察

查看当前阶段、计划步骤、工具调用、确认状态与执行结果。

Knowledge

知识与记忆

导入文档、建立向量索引，并用摘要减少长对话的上下文压力。

Tasks

后台任务

把耗时工作从聊天请求中拆出，支持状态查询、暂停和取消。

前端不是“包装层”，而是智能体可解释性与安全交互的一部分。

03 / Architecture

六层协同架构

交互层React / Vite · 对话、确认卡片、Runtime Inspector、任务与知识库界面
API 层FastAPI · 认证、会话、流式聊天、工具确认、任务、知识库与记忆接口
Agent 运行时LangGraph · 上下文装配、检索、规划、工具决策、回答生成与持久化
能力层ToolExecutor · 内置工具、Web Search、Fetch MCP、GitHub / Hugging Face 路由
知识与记忆层RAG · 文档切分、Embedding、向量检索、记忆摘要与上下文压缩
数据层PostgreSQL + pgvector · 用户、会话、消息、工具审计、任务、知识文档

04 / Runtime graph

一次请求如何完成

01确保会话校验用户、创建或恢复 conversation
02装配上下文历史消息、系统约束、能力配置
03检索知识按需召回知识片段与记忆摘要
04规划动作识别意图，选择直接回答或工具路线
05执行工具验证、确认、调用、记录与结果归一化
06生成回答综合上下文与工具结果，流式输出
07持久化保存消息、调用记录与后续摘要素材

LangGraph 让每个阶段都可测试、可插拔，也为失败恢复与后续扩展保留位置。

05 / Streaming contract

SSE 是前后端的共同语言

status→ plan→ tool_call→ tool_result→ token→ done error
Visible state

用户知道正在发生什么

检索、等待确认、工具执行和回答生成都有明确状态。

Stable UI

确认界面不会被流刷新冲掉

前端围绕事件契约维护稳定的 pending tool 状态。

Clean output

协议文本不进入用户回答

工具协议与用户可见 token 分离，避免原始调用标记泄漏。

07 / Knowledge & memory

让上下文既丰富，又不会无限膨胀

Knowledge / RAG

把外部资料变成可检索证据

  • 文档导入与清洗
  • 切分、Embedding 与 pgvector 入库
  • 按当前问题召回相关片段
  • 将证据注入本轮模型上下文
Conversation / Memory

把长对话压缩成可延续线索

  • 近期消息保留原文细节
  • 较早历史提炼为摘要记忆
  • 重要偏好与任务状态持续沉淀
  • 在成本、速度与连续性之间平衡

08 / Search routing

不同链接，走不同能力路线

Direct URL

通用网页

交给 Fetch MCP 抓取与摘要，保留确认、超时和审计行为。

mcp.fetch.fetch
Repository-aware

GitHub 链接

优先使用仓库感知工具，理解目录、代码与提交语义。

github mcp
Model ecosystem

Hugging Face

按模型、数据集或论文对象路由，避免退化为普通网页抓取。

hf-aware tools
Freshness

最新信息

“今天、最新、新闻、来源”等意图触发 web_search，再选择结果抓取。

web_search → fetch

09 / Background work

耗时工作，不必绑住聊天请求

Lifecycle

可观察的任务状态机

pending→ running→ completed failedcancelled

任务记录进度、结果与错误，支持暂停、恢复或取消。

Why it matters

把交互延迟与执行时长解耦

  • 聊天请求能快速返回状态
  • 长任务可以独立重试与审计
  • 后续可接入队列、调度与通知
  • 为真正的异步 Agent 工作流打基础
